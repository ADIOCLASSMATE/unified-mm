**B 大规模训练：I2T / T2I 数据缺口与合成建议（2026-09-11）**

> 历史记录：本文描述当时的协议和实际产物。当前执行以 [DATA_SYNTHESIS.md](DATA_SYNTHESIS.md) 为准：复用优先、SII 补缺纠错、重试耗尽后才用 Codex CLI；连接信息只从 SII 环境变量或静态 shell rc export 读取。

按 2026-09-12 用户更新后的流程，先选择覆盖缺口的现成图片，通过无 VPN/代理的下载客户端取图，完成 **512×512** 预处理，再使用现有 **Codex CLI 的 GPT-5.6-sol low** 直接为实际训练视图合成 I2T/T2I。Qwen API 合成已停用。每批最多 8 张图，生产并发从 16 路自适应增加到 128 路；每图产出一条 I2T 与一条忠实 T2I，合格旧文本重新验图后原样复用。Codex 保留既有代理连接。当前最大的投入机会是新增不同的图像和实体关系；继续给同一批 ImageNet 图片生成同义描述，收益可能有限。纯文本沿用现有 ClimbMix，本方案只讨论图像数据。当前实现与独立 public 目录见 [Codex 合成流程](B_CODEX_IMAGE_SYNTHESIS_20260912.md)，图片来源建议保留在 [原执行设计](B_IMAGE_TEXT_SYNTHESIS_V1_20260911.md)。

本分析对应正式 **B / b_x0，Qwen3-0.6B-Base 初始化，step 95,415 final EMA**。核对了实际训练配置、loader、已发布数据、B 的逐项评测和部分定性图片；另外以 seed 20260911 均匀无放回抽查 2,048 张训练图的文本，覆盖 870 个 synset。没有运行新的模型评测，也没有估计全库人工标注准确率。后文的混合比例、数据规模和验收阈值都是建议起点。

**当前配方已经提供了什么**

| 项目 | 核实的实际状态 | 对扩大的含义 |
| --- | --- | --- |
| 图像来源 | ImageNet train，1,281,167 张 | 具有物体类别和细粒度外观基础，不能等同于开放世界场景覆盖 |
| I2T | Qwen / MiniMax 各 3 条，每图 6 条，合计 7,687,002 条；original 不参与 | 多教师提供了措辞和关注点差异，仍围绕相同像素 |
| T2I | 每图固定 12 类 prompt，合计 15,374,004 条；全部指向原图 posterior | 文本风格扩展没有对应的图像风格扩展 |
| 图像表示 | 256×256，256 个 KL16 latent token | 小字、小物体、拥挤场景和长宽比会受到输入限制 |
| 图像序列 | 长度 512，图像与特殊 token 占 259，文本总预算 253 token | 新增长 caption / 文档不能只替换数据路径；当前 loader 超长会报错，不会自动截断 |
| I2T 格式 | 固定 `Describe this image in one detailed caption:` | 已学习描述，不等于已经学习视觉问答、区域指令和多图推理 |
| 每任务曝光 | 按配置推算约 97,704,960 图次，约 76.26 次遍历 | 这是重复曝光，不是近亿张不同图像；flow batch multiplication 也不增加不同图片 |

本次抽样的 12,288 条训练 caption 平均 48.91 词、中位数 49 词、P95 为 61 词；24,576 条 T2I prompt 平均 25.32 词。每张图的六条 caption 合并后，88.33% 出现 left/right/above/below，39.84% 出现 2–10 的数字或英文数词，18.12% 出现文字相关词，2.39% 出现 no/not/without。这些只是词面探针：`two hands` 不能算完整计数监督，`letters` 不等于准确转写，出现 left 也不能证明实体绑定正确。

因此不应把问题概括为“没有关系词或没有数字”。更准确的缺口是：**关系与数量缺少结构化真值、多主体和罕见组合不足、长文本中的事实约束没有逐项核验。**

**应首先处理的 T2I 配对问题**

12 个 slot 顺序为 faithful_photo、cinematic、macro_detail、environmental_wide、studio_editorial、golden_hour、low_key、watercolor、graphic_illustration、three_d_render、surreal_concept、documentary_action。Loader 轮换这些文本，但目标始终是同一原图。具体实现见 [T2I 文本选择](../utils/dataset_imagenet_flow_cache.py) 和 [数据来源说明](../output/evaluation/data-provenance/README.md)。

例如训练图 `train/n01440764_10026` 的 faithful 文本描述草地上持鱼的人；其他 slot 要求水彩、3D、鱼鳞发光、黄金时刻光照或手和鱼的特写，却没有这些变体的图像目标。`train/n03032252_11293` 的 surreal 文本要求影院字母像发光丝带一样伸出来，目标也仍是原图。

每个完整轮换中仅 1/12 是明确的 faithful_photo slot。这**不代表其余 11/12 全部错误**，一些摄影描述可能仍与图像兼容；但原图不能自动成为水彩、改变构图或新增物体之后的正确监督。其机制风险是模型学会忽略风格、光照和部分细节要求。B 已有风格失败样例与此一致，但尚无单变量实验能证明这就是唯一原因。

建议为新配方建立两类合法图文对：

- 原图搭配忠实描述：短、中、长描述，以及强调已有属性/关系的描述。先复用通过核验的现有六 caption 和 faithful_photo，不必把全部文本推倒重做。
- 风格、物体、位置和数量从所下载图片的真实可见内容提取，再合成相应 prompt；当前阶段先选已有这些属性的图。未来如果实际生成/编辑新图，必须在验图后重新计算该图的 posterior。

同一图片可以拥有不同粒度的真实描述；不能因为文本来自同一图片就假定所有改写都成立。

**从 B 下游结果看 I2T 的优先级**

| 能力与指标 | B 保存的结果 | 对数据的判断 |
| --- | ---: | --- |
| ImageNet 分类 Top-1 / Top-5 | 44.94% / 72.02% | 细粒度类别、名称对齐仍可补；不能将差距全归因于数据 |
| COCO 5K 检索，图→文 / 文→图 R@1 | 24.60% / 22.19% | 日常多主体场景及短 caption 匹配值得补 |
| Flickr30K 1K 检索，图→文 / 文→图 R@1 | 38.30% / 43.94% | 人物、动作、交互的泛化仍有空间 |
| SugarCrepe 总体 | 77.03% | 总分掩盖类别差异 |
| SugarCrepe replace_rel / add_att / swap_obj | 68.28% / 69.65% / 71.43% | 优先补关系、无依据属性、主体角色交换 |
| ARO Relation / Attribution | 64.15% / 67.26% | 关系和属性绑定需要更严格监督 |
| SEED 计数 / 空间关系 / 实例位置 | 34.12% / 34.40% / 35.28% | 做可核验的计数、位置、指代数据 |
| SEED 场景理解 | 48.16% | 比计数/位置强，但不同题型不可当成同难度实验 |
| MMBench 粗感知 / 关系推理 / 逻辑推理 | 60.47% / 36.52% / 28.81% | 从“描述大致是什么”过渡到“按问题提取证据” |

这里的检索“文→图”是理解评分中的检索方向，不是 T2I 图像生成。分类、检索、组合任务使用项目的语言先验校准生成式评分；MMBench 是 circular 指标，SEED/MMBench 仅作项目内部诊断，不能直接套官方自由生成榜单。

**ARO 的低分类分数需要先辨别校准效应。** 例如 wearing 共 949 条，正式校准分数为 33.83%；从已保存的候选分数还原未校准条件似然后，严格胜率为 88.83%，其中 541 条由正确变为错误。与此同时 SugarCrepe 总体由未校准 62.42% 升至正式 77.03%。这说明不能整体取消校准，也不能把 wearing 的 33.83% 直接解释成“模型几乎不认识穿衣关系”。原始似然高也可能依赖语言常识，并不证明看图。需要在独立开发集上检查真实图、错配图、空图分数及可逆角色对；本分析保持既有正式指标不变。

| I2T corner case | 具体例子 | 所需监督 |
| --- | --- | --- |
| 多实体属性绑定 | 红衣人拿蓝杯，蓝衣人拿红杯；同一组词交换归属 | 每个实体绑定独立 ID、属性、关系；相似场景的最小差异图文对 |
| 非显著物体与完整计数 | 桌上 5 个杯子，其中 2 个透明、1 个被遮挡；背景小目标 | 框/点/实例 mask 与可见性；数“物体”而非描述中数词的频率 |
| 相对位置和参照系 | 杯子在盘子左边，盘子在书前面 | 明确以画面还是物体自身为参照；左右、上下、前后分别验证 |
| 动作和角色 | 人牵狗、狗追人；手拿杯子而非杯子在桌上 | 人物姿态、接触点、动作动词与主客体；静态图不臆测前因后果 |
| 无依据细节与否定 | 没有戴帽子；被遮住的字无法辨认 | 可验证范围内的“没有/无法确认”，避免把模糊图补成常见情节 |
| 细粒度与长尾 | tench 不被泛化成 carp；同类车型、器具、材质区别 | 可靠源标签 + 可见鉴别特征，避免教师强猜不清晰的细分类 |
| OCR 与文字落点 | 读出商品名，判断哪块牌子的箭头指向左侧 | 转写字符串、文字区域和布局绑定，保留看不清的情况 |
| 图表、文档、界面与图解 | 比较柱高、读表格交叉单元格、理解箭头连接 | 源数据/渲染代码作为真值；问题需要的信息必须在模型视野内 |
| 开放问答、比较与多图 | 只回答哪个物体更大；比较两张图变化 | 独立的指令/多图数据格式；当前 caption loader 没有覆盖 |

前五项有当前分项评测支持。OCR 有少量 SEED 题与定性线索，但尚无足够专项测量；文档、图表、界面、多图等主要是现有训练任务和评测范围之外的缺口，不能声称已测得其失败率。中文图文也没有形成系统训练覆盖；若大模型面向中文使用，需要专门的中文图文与中英文字渲染，ClimbMix 本身不能补视觉文字识别。

**T2I 已见失败与尚未覆盖的角落**

B 的 ImageNet-val FID50K 在 CFG=2.0、Heun10、Halton 时为 **4.245**；CFG=3.5 时为 **5.207**。这说明 ImageNet 条件分布已有较好的项目内结果，不能说明复杂 prompt、艺术风格或文字生成已解决。FID 不是逐条约束完成率；本项目指标也不按 ADM/DiT 官方榜单直接比较。[CFG2 结果](../output/evaluation/ablation-matrix/cfg2-heun10-order-20260909-r1/arms/b-x0-halton/metrics.json)

I2T 定性样例也出现文字补全问题：`mscoco_10` 的 caption 声称黄色消防栓有写着 FIRE 的红牌，保存的模型输入图并不能支持该字符串。应把“红色牌子”和“牌子写什么”分成两条独立核验的事实。[输入图](../output/evaluation/qualitative/unified-all-final-ema-20260908-r1/inputs/mscoco_10.png)、[生成文本记录](../output/evaluation/qualitative/unified-all-final-ema-20260908-r1/results.jsonl)

| T2I corner case | 为什么当前配方不够 | 建议补法 |
| --- | --- | --- |
| 精确计数，0/1/2/3/4/5+ | 自然照片中数量分布不均，多 caption 不增加新的数量状态 | 同场景控制实例数，保留可见性真值；真实多物体图配精确描述 |
| 属性归属与角色互换 | 学会“有红色/有蓝色”不等于颜色各自绑定到正确物体 | 颜色/材质/大小交叉组合，每次只换一个属性并同步换图 |
| 左右、前后、包含、遮挡 | 全局像不像不惩罚所有关系错误 | 结构化布局、视角/深度控制；真实与渲染数据混合 |
| 3–6 个实体、多条约束、长 prompt | 当前 prompt 平均约 25 词，目标多偏主体居中 | 分层增加实体数和关系数；评估所有约束是否同时完成 |
| 人体、手、人与物接触 | 类别库不能提供充分交互覆盖 | 多人物、手势、运动、工具操作和职业场景，核对接触/持握位置 |
| 水彩、插画、像素风、3D 与设计图 | 风格文本经常仍监督为照片 | 使用真正风格图及对应 caption；合成实际风格变体 |
| 图中文字及中英混排 | 文字常被概括为 sign/letters，256px 也损伤笔画 | 字符串驱动的程序渲染、场景字数据、逐字 OCR 校验 |
| 反常组合与视觉常识冲突 | 同图改文没有增加反常组合的视觉证据 | 例如玻璃材质日常物体、非典型物体共现；生成成功才收录 |
| 反射、透明、阴影、重复结构 | caption 容易提到效果但不保证几何一致 | 可控渲染及真实精选，分别检查反射/投影与实体对应 |
| 非正方形与全局构图 | 固定中心裁剪可能丢边缘主体和文字 | 保存原始长宽比，准备适配架构的 aspect-ratio bucket 与完整视野 |

正式 B 当前没有找到有效的 GenEval / DPG-Bench / MJHQ 完整官方评分。因此可以说上述样例失败、这些类别需要覆盖，不能给 B 填一个推测的 GenEval 或 DPG 分数。后续应按 [GenEval 六类](https://github.com/djghosh13/geneval)、[DPG-Bench](https://github.com/TencentQQGYLab/ELLA)、[MJHQ-30K](https://huggingface.co/datasets/playgroundai/MJHQ-30K) 分开测对象组合、复杂文本和图像分布质量；文字生成还需专项评测。

**推荐加入哪些图片**

下表的规模为数据发布方标称规模或公开 split 数量，不等于今天可成功下载、去重并验收的数量。优先级依据本项目 B 的缺口，不是数据集通用排名。

| 优先级与数据源 | 用途与获取价值 | 合成方式及筛选重点 |
| --- | --- | --- |
| P0：现有 ImageNet | 保留细粒度物体、外观和现有基础 | 校验原 caption；把合格 caption 用于 T2I；补短类名描述和可见鉴别特征 |
| P1：[Open Images V7 + Localized Narratives](https://storage.googleapis.com/openimages/web/factsfigures_v7.html) | 约 9M 图，约 1.9M 有框等密集标注；有关系和局部描述。优先补真实多物体、人物、动作与位置 | 先取 train 中有框/关系/叙述的部分；将人工标注作为锚点，合成全图及实体关系描述。不能把标注缺失当作对象不存在 |
| P1：[PixMo-Cap](https://allenai.org/blog/molmo) | 约 712K 不同图、约 1.3M dense captions；覆盖多种主题，提供人类描述来源 | 保留有效人类信息，合成短描述和实体事实，不必全部从零重写。先核验下载成功量及长文本适配 |
| P1：[CC12M](https://github.com/google-research-datasets/conceptual-12m) / [Recap-DataComp-1B](https://huggingface.co/datasets/UCSC-VLAA/Recap-DataComp-1B) 精选 | 构成 10M–30M 级开放场景的候选池，扩大不同图片和长尾概念 | 先下载/去重/按内容分桶，再对低质量或重点类 recaption；Recap 的现有描述可作候选，不作免检真值。均不能把 URL 数直接当可用图数 |
| P1：[Objects365](https://www.objects365.org/overview.html) | 约 2M 图、365 类、30M 框，补自然场景物体清单 | train 框辅助实例枚举、数目、相对位置；前后/接触关系不能仅凭二维框猜测 |
| P1 小规模高质量：[DOCCI train](https://huggingface.co/datasets/google/docci) | train 9,647 图，有详细人工描述；适合检查长描述中的计数、关系和差异 | 作小比例高质量训练与合成规范参考；保留 test 5K，勿按名称把所有约 15K 一并训练 |
| P1/P2：[JourneyDB train](https://github.com/JourneyDB/JourneyDB) | 约 4.19M 有标签训练图，补真实存在的合成视觉风格与复杂场景 | 按最终图像重新核实主体、数量与风格；原始生成 prompt 可能有模型未画出的要求。先精选 0.5M–2M；下载入口需要按其说明申请，使用自定义条款 |
| P1 小规模：[BLIP3o-60k](https://huggingface.co/datasets/BLIP3o/BLIP3o-60k) | 已有合成图文覆盖常见物体、人物、文字和组合，可低成本验证合成图是否有效 | 用实际 tar 清单计数；官网 viewer 的 prompt 行数不是图片数。逐源排查 COCO 等来源及评测 prompt 重合 |
| P1 专项：[TextCaps](https://arxiv.org/abs/2003.12462)、[AnyWord-3M](https://github.com/tyxsspa/AnyText) | TextCaps 约 28K 图/145K 描述；AnyWord 提供文字图像数据。补 I2T 读字和 T2I 写字 | 使用训练 split；文本串与区域绑定，并在最终训练分辨率上确认可读。数据带有额外文字控制字段，不代表 B 已支持对应控制接口 |
| P2：[PixMo-Docs / CoSyn-400K](https://github.com/allenai/pixmo-docs) | 文档、图表、表格、图解等，可以复用公开程序化合成流程 | 从渲染源构造事实/QA，比让 VLM 猜数字可靠；I2T 优先，T2I 只放语义条件能明确决定的图形任务 |
| 条件加入：[COCO](https://cocodataset.org/)、Flickr30K、[Visual Genome](https://visualgenome.org/home) / [GQA](https://cs.stanford.edu/people/dorarad/gqa/about.html) | 对现有检索/组合评测内容很相关；VG/GQA 有场景图和关系 | 先按下文排除评测原图和所有派生 crop/caption/QA。若要保留跨数据源泛化论点，优先用前面的独立来源，不加入这些来源训练 |

大规模池不应只按 aesthetic 或单一 CLIP 分数取最高分：这会使拥挤场景、小物体、OCR、长尾关系等难例再次被筛掉。建议先做内容分桶，再在桶内按清晰度、配对正确性和任务需要筛选。I2T 可以保留真实世界难图；T2I 应更强调成像质量和可控条件，两个任务不必完全共用采样权重。

**合成流程应以可核验事实为中心**

本轮流程是：`按能力桶选图 → 下载/去重/排除评测来源 → 预处理并冻结训练视野 → Codex sol low 附图合成 I2T/T2I 或确认旧文本可复用 → 严格审计 → 分片缓存与采样`。可以下载已有合成风格图作为图片来源；本轮重点是对选定图片合成忠实文本。以下可控新图部分作为后续补充选项。

对真实图片，教师观察实体、类别、可见属性、可见数量、位置、明确关系、可读文字和图像风格。已有框/点/文字真值作为后续核验锚点。普通图仅返回两条文本及简短标签，重点能力桶才额外返回紧凑事实字段。以下是可配置的文本视图，首轮每张图选一条 I2T 和一条 T2I；额外视图只在实测需要时生成：

| 文本视图 | 建议内容 | 训练用途 |
| --- | --- | --- |
| 短描述 | 15–30 词，保留主要实体和最有区分力的动作/关系 | 贴近自然检索文本、短 T2I prompt |
| 完整描述 | 60–120 词，按实体展开，少写空泛的气氛和审美措辞 | I2T 全图理解；T2I 密集条件 |
| 聚焦描述 | 1–3 个经过核验的属性、计数或关系，文字短但信息明确 | 使小对象和关键关系不会被全图 caption 淹没 |
| 视觉 QA / 指代 | 仅在启用对应数据格式后，按图中证据回答一个问题 | 后续指令训练或明确标记的混合训练，不直接塞入旧 caption 字段 |

首轮维持原生图文预训练，可先用前三类，并为短/详细描述配置相应前缀。若大模型还要在 VQA/图表/指令理解上有实际可用性，再设置独立的图像指令阶段；这会改变当前 `instruction_tuning=false` 的实验口径，需要同时报告指令阶段前后的结果。

不要机械要求每图六条。当前每图一对 I2T/T2I，把更多合成预算投入多主体、文字、长尾场景和歧义关系。现有 Codex CLI 的 GPT-5.6-sol low 直接批量附图合成；旧文本只有与当前图片一致才原样复用，否则同次调用重写。结合框/点/OCR/源数据核验，模型输出可用标记不等于独立事实验证；抽查按能力桶开展，避免只随机看漂亮图片。

对可控新图，先采样 scene graph，再出图，并记录生成器版本、随机种子、对象与渲染参数。应刻意平衡物体、属性、位置和数量的交叉分布：红色不总绑定苹果，左侧不总是更大物体，同一布局中轮换主体身份。不要只扩写现有 benchmark 的几百条 prompt。

可控合成的三个重点：

1. **数量/布局/属性。** 用 [CLEVR 的场景与问题生成代码](https://github.com/facebookresearch/clevr-dataset-gen) 所体现的程序化思路构造可检查状态，逐步增加真实物体素材、背景、材质和光照。简单渲染适合真值，不应成为全部图像分布。
2. **文字/图表/文档。** 先生成字符串、表格数值或连接图，再用程序渲染图像，保留字框、单元格和边连接。可参照 CoSyn 的 HTML、LaTeX、图表流程；自然场景字也要逐字核验。
3. **艺术风格/复杂真实感。** 使用能力通过小样本验收的图像生成或编辑教师，对同一内容做真正的风格变化；每次只改变一个关键因素，随后检查其他事实是否被意外改变。不要假定生成教师天然能准确计数或完成长 prompt。

生成图必须同时过全图质量和原子约束检查。若要求五个物体却生成四个，可重生成；若改写为“四个”保留，也必须重分配到四物体桶，不能算五物体成功样本。T2I 文字要求变了，就必须有满足新要求的目标图。

负例优先选择语法自然、两种情况都可能在真实世界发生的最小差异，例如“猫在椅子下面 / 猫在椅子上面”，并构造相对应的图片。`shirt wearing man` 一类不自然交换会引入语言捷径。负文本可用于数据验收和独立诊断；如用于训练，需要显式的匹配判别或 ranking 目标。**不能把错误 caption 当普通 I2T 正目标计算 NLL。** 现有 B loader 不具备负例训练目标。

**数据前处理会决定合成标签是否仍然成立**

当时的 VAE 编码脚本采用 Resize 短边 + CenterCrop；caption 教师读取原图全幅，大图按输入上限等比缩小。抽样记录中 516/2,048 张（25.20%）长短边比超过 1.5，226 张（11.04%）短边低于 256。这些是裁剪/细节风险信号，不是已确认错误的比例。[编码流程](../scripts/imagenet_encode_kl16_vae.py)、[历史字幕与图像输入协议](../configs/protocols/evaluation_data_sources.json)

新数据应先确定训练视野，再合成或校验 caption。裁掉边缘物体后，原来的“共五个”可能只剩四个；左右关系和字框也要按实际裁剪重新计算。读字与文档需要在模型看到的分辨率/重建视图上检查，不能把教师在原始大图里读到、B 输入里已经消失的字作为必答目标。

用户已确定直接使用 512px：按当前 KL16 空间下采样关系，对应 1,024 个图像 token，建议图像分支序列长度起点为 2,048，纯文本分支保持现有设置。位置编码、缓存、batch 和验证均需同步适配；增加模型参数不能恢复已被裁掉或降采样抹掉的信息。当前编码脚本仍有固定网格假设，具体位置见执行设计；本轮尚未完成代码修改或 512px 设备验证。

**建议的规模、混合比例与验证顺序**

在没有确定大模型参数量和训练图次预算前，建议先做 **250K 新图的生产验收批次，再扩成新增 2M + 现有 ImageNet 的约 3.28M 验证库，最后到 20M–30M 通过验收的不同图片**。每图默认一条 I2T 与一条 T2I；先确定真实可用图数，不按原始 URL 数或 caption 数报规模。此轮先用现成图片填满能力桶，可控新图生成留作后续独立实验。

下面是两个图像任务内部的**有效图次采样比例**，不是总训练 token 比例，也不是磁盘上不同图片的占比。互相重叠的数据按主要用途归入一个桶，避免重复计算；所有数值都是首轮假设，按开发集结果调整。

| 主用途桶 | I2T | T2I |
| --- | ---: | ---: |
| 开放真实场景：CC12M/Recap 精选、Open Images、PixMo | 40% | 45% |
| 物体密集、动作、关系与计数的真实数据 | 25% | 15% |
| ImageNet 与细粒度类别保留 | 10% | 10% |
| 真正的艺术/设计/高质量生成图 | 5% | 15% |
| 经过核验的组合能力图（现成图库优先） | 10% | 10% |
| OCR/图表/文档/文字图 | 10% | 5% |
| 合计 | 100% | 100% |

I2T 的文档/QA 部分应随 serializer 支持逐步增加；首轮 512px 单图 caption 先选实际可读的场景字和图形。T2I 的最后一桶以明确文字或图形内容为主，不能把只有局部 QA 描述的复杂整页当作充分的整图条件。

建议按以下顺序验证，固定 B 架构、初始化、图像有效曝光、训练预算和评测方式：

| 对照 | 改动 | 回答的问题 |
| --- | --- | --- |
| D0 | 当前数据配方复现基线 | 为数据实验提供同预算起点 |
| D1 | 同一 ImageNet 图库，只修正 T2I 图文配对 | 风格/条件失配究竟影响多大 |
| D2 | D1 + 新真实图片，用基础忠实 caption | 新视觉覆盖的贡献 |
| D3 | 与 D2 相同图库，增加实体/关系事实视图 | 标注质量和监督结构的贡献 |
| D4 | D3 + 含目标组合/风格的现成图片，以及忠实合成文本 | 补图是否改善组合/风格缺口；未来实际生成新图另列对照 |

每个对照可先用 5M–10M 有效图次/任务做方向性实验，预算合适时重复 seed。建议把“独立组合开发集提升约 3–5 个百分点、主要真实图任务无明显回退、分桶事实准确率达到预设门槛”作为待验证的扩大条件；这些不是已取得的收益或对最终模型的承诺。先预设阈值和误差估计，再看结果，避免围着少数现有失败样例优化。

仍保留现有 ImageNet FID 和理解指标用于连续比较；补齐 B 原版及新配方的官方 T2I 评测。建立与训练独立的分桶开发集，分别看关系、数量、颜色归属、OCR、风格、多实体所有约束完成率；不要只看总体分或 caption 长度。自由 caption 用人工事实核验区分漏说与编造，VLM 评审作为辅助；OCR 以字符串准确性、计数以实例真值核验。

**评测来源必须在合成之前排除**

这对本项目非常具体：本次从保存的预测来源统计，SugarCrepe 的 7,511 条题涉及 **1,560 张 COCO 原图**；与当前 Karpathy test 5K 仅有 **183 张交集**，两者合计 **6,377 张不同 COCO 原图**。因此只排除 Karpathy test，再把其他 COCO 图片全拿去合成，会把 SugarCrepe 的部分图片引入训练。SugarCrepe 官方说明其图片来自 COCO-2017 val。[官方来源](https://github.com/RAIVNLab/sugar-crepe)

ARO Relation 和 Attribution 分别涉及 **5,316 / 4,517 张 VG 原图**，并集 **6,603 张**。排除时必须排除整张原图及其所有 crop、caption、scene graph、QA，不能只删除发布的那一条关系。VG、GQA 和其他混合数据中的同一原图需要共享身份。[本次来源统计](../output/evaluation/data-strategy/b-20260911/audit.json)

正式数据发布前还应合并 Flickr30K test、MMBench/SEED、ImageNet-val、MJHQ 参考图，以及用于验收的新增开发/测试图的排除清单。合成的同一源图、同一 scene graph 家族及其图像变体放在同一 split；开发/测试要留出实体组合和模板家族，避免只改随机种子或措辞。原图 ID/URL 加离线视觉近重复筛查用于数据准备，不在训练运行时开启 hashing。

GenEval、DPG 和固定定性集的测试 prompt 不用于教师生成训练图。可以训练同类能力，但要使用独立的组合和语言模板；BLIP3o 等来源声称无测试重合也仍需对本项目固定版本检查。

如果加入 COCO/Flickr/VG 的训练子集，即使完全排除了测试图，这些来源的评测也应改称“同来源留出评测”，不能继续沿用当前全部外部 benchmark 都是来源域外的表述。保留另外的未用于训练的数据源，可继续测真正的跨来源泛化。

**落地时需要的最小数据工程**

建议采用一个共享图片库、两个任务采样视图：图片与 posterior 只存一份，I2T 和 T2I 分别维护合格文本、采样权重与任务标签。单条记录至少保留 source_dataset、source_id、split、parent_image_id、crop/resize、图像尺寸、caption 类型、教师与 prompt 版本、事实及验收结果、latent shard/offset。生成图另外保留生成来源和场景参数。

现有 loader 已使用 mmap 并让 I2T/T2I 共享 posterior；可沿用这一思路。需要补充跨数据源 shard manifest、任务独立的采样权重、每条样本的指令格式与新的分辨率配置。按新方案 FP16 mean+std，每张 512px posterior 为 `1024×32×2 = 65,536 bytes`；20M 图约 1.31 TB、30M 图约 1.97 TB，仅统计 posterior，不含 RGB、文本、索引和多视野副本。分片主要是为了分布式 I/O、版本化和恢复，不是因为当前代码没有 mmap。

按投入顺序，先确定 Open Images / PixMo、CC12M / Recap、JourneyDB、文字图片的下载配额，排除评测原图并完成预处理；再用 Codex sol low 合成与处理后图片一致的文本。当前先利用已准备好的 103,351 张图片启动生产，后续扩展图片来源时继续沿用同一验收要求，再把通过验收的配方用于大的 B。
