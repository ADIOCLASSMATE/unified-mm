# S2 infra

模型与训练预算见 [S2 / SigLIP](SHOWO2_UNIFIED_ABLATION_DESIGN.md)。以下调优保持四份 time/noise、任务曝光、loss 归一化和 optimizer 设置，调整 activation checkpointing 与 MC 执行方式。

## 性能

设备为单节点 16×910B，正式每卡 batch 4/16/4/16、GA4。正序与逆序各跑一次，每段 6 updates，去除前 2 次，以最慢 rank 时间的中位数计。

| 执行组合 | single 秒/update | dual 秒/update | single GiB | dual GiB |
| --- | ---: | ---: | ---: | ---: |
| 逐层 + 完整预测 checkpoint，MC 串行 | 3.833 | 4.932 | 9.77 | 11.64 |
| 逐层 checkpoint，MC 合批 4 | 2.977 | 4.104 | 9.77 | 11.64 |
| 仅 backbone checkpoint，MC 串行 | 3.106 | 4.170 | 18.55 | 35.40 |
| 仅 backbone checkpoint，MC 合批 2 | 2.961 | 3.808 | 18.64 | 35.49 |
| 仅 backbone checkpoint，MC 合批 4 | 2.918 | 3.887 | 19.77 | 36.62 |
| Backbone 隔层 + semantic checkpoint，MC 合批 4 | 2.693 | 3.964 | 43.00 | 45.30 |

## 当前执行配置

| 控制 | S2-single | S2-dual-siglip |
| --- | --- | --- |
| `s2_mc_batch_size` | 4 | 1，串行执行四份样本 |
| `s2_full_prediction_checkpointing` | false | false |
| `image_flow_grad_checkpointing` | false | false |
| `s2_backbone_checkpoint_every` | 2 | 1 |
| `s2_semantic_gradient_checkpointing` | true，single 无此分支 | false |
| 相对初始配置吞吐增幅 | 约 42% | 约 18% |

Single 完全关闭 checkpoint 会在 T2I 前向 OOM。Dual 的 MC2 梯度全局相对 L2 偏差为 17.7%，因此使用 MC 串行。

## 数值与恢复

数值比较使用 single checkpoint-6000 / dual checkpoint-4000、真实 prompt 和 ImageNet posterior。接受阈值为 loss 相对误差 0.2%、每参数梯度相对 L2 误差 3%。

| 对照 | 结果 |
| --- | --- |
| Single checkpoint 调整 | 全局梯度相对 L2 2.20e-8 |
| Single MC4 合批 | 全局 0.642%；最坏单参数 2.31%；loss 2.65e-5 |
| Dual checkpoint 调整 | 全局 1.50e-7；最坏单参数 0.0136%；loss 相同 |
| 6→12 step infra 迁移 | 完整 checkpoint、raw/EMA 重载、图文生成通过 |
| 12→18 step 严格续训 | 通过，并采集三次更新的 Level1 profiler |

Profiler 的计算／未重叠通信／空闲占比：single 为 93.05% / 3.94% / 3.01%，dual 为 83.17% / 9.09% / 7.73%。独立吞吐使用上表无 profiler 的计时。

正式 64 卡任务从各自完整 checkpoint 恢复，配置保存在 run 内的 `config-infra-20260910.yaml`。Launcher 的 `--allow-infra-migration` 允许表中执行控制变化，并写 `infra_resume-<step>.json`；恢复 world size、数据、optimizer、scheduler、GA 与 EMA。
