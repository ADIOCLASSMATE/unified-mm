## 范围与运行约束

- 图像池：[固定协议](../configs/protocols/unified_b_prepared_frozen_20260914.json)，只读引用已有图片和 prepared batch；下载保持关闭。
- 模型：只允许 SII `qwen3.8-max`，要求返回模型标识一致；所有生产候选图像必须真实解码并附图。
- 连接信息：只读环境或静态 shell rc 中的 `SII_API_KEY`、`SII_BASE_URL`；不读取 `test_api.py`。
- 不启用 Codex CLI 接管，不切换其他模型，不计算数据哈希，不修改全局代理、路由或 DNS。
- 本轮只复核和保存文本/证据；不启动 posterior 编码、训练导出或训练任务。
- 原始 prepared 数据不覆盖，保留原始 caption、标注和来源引用。

## 已修复的直连传输问题

P-256、TLS 1.2、HTTP/1.1 握手可以成功，但默认 TCP 分段的真实图片上传超时。同等大小的纯文本请求也在上传阶段超时，不能解释为模型视觉质量问题。

普通 httpx `socket_options` 在建立连接之后才设置 `TCP_MAXSEG`，无法调整 SYN 中协商的 MSS。本轮新增独立网络 backend，在连接前设置 MSS=512，实际协商得到约 500 字节；真实 512px 图片已返回完整内容。保留 TLS 证书和主机名校验；图片原字节不压缩、不缩小。所有变化仅作用于 SII 客户端连接。

## 抽样与质量验证

自然样本共 320 张，8 个来源层各 40 张：Long/CC12M、Long/SA-1B、Long/JourneyDB、PixMo-Cap、PixMo-Points、Open Images、PD3M、TextCaps。层内对合格记录均匀抽样、不放回，随机种子 20260914。

增加 80 条明显错误 caption 对照，使用相同真实图片配不相符的空白图描述；这些是诊断请求，不加入训练。此对照只能检验明显错配，不能证明精细 OCR、计数和空间关系能力。

GPT-6 直接查看 32 张代表性自然图片（每层编号 00、10、20、30）的实际 512px 视图，核对输出。初版主要问题包括：小字菜单价格错误、补全被裁切的邮票文字/年份、臆测微小水印网址、给复杂拼贴添加不可靠精确计数。

第二版加强了裁切、小字、背景计数和预处理填充边界的规则。同一批 400 条重测，精确计数明显减少，但仍发现菜单 `£8.50` 被写成 `£5.50`，以及裁切邮票文字补全等错误。因此不能出具通过报告。另有 32 张开启 Qwen 推理模式的对比测试；最终结果保存在独立目录。

放量必须同时满足：试跑全部请求完成且无未解决的格式/传输失败；输出和原始 API 响应能对应；错误对照能被识别；实际视觉检查未发现未解决的关键事实错误。不存在程序自动根据成功率签发 GPT-6 视觉资格的逻辑。

## 代码入口与断点保存

入口：`python -m scripts.review_b512_sii sample|pilot|bulk`。运行配置必须显式提供，复核配置关闭 Codex fallback；bulk 必须提供实际通过的 `--qualification`，绑定同一模型配置、prompt 版本和固定图像范围。

新复核流程和旧的“免 API 复用优先”流程分开。全量队列以固定的 179,088 个来源批次为基础，每 64 个来源批次组成一个有独立 SQLite/WAL 状态的处理分片。分片内所有身份先持久化再请求；使用单写入者、持久化原始回复、按条重试、网络熔断和自适应并发。停止信号会停止补充请求并排空在途结果。

每片结束后写 `reviewed.jsonl.gz`，保留原图引用、I2T/T2I、复核决定、问题、模型和证据数据库路径；逐条重新校验与原始 SII 响应的一致性，完整读取 gzip 并核对计数，然后原子写出 `manifest.json`。失败不会伪装成成功；存在终态失败则标记 `needs_attention`。结果可用于后续处理，但不自动触发下一阶段。

当前配置默认并发从 16 增长到 128，受 RPM/TPM 和熔断共同限制。推理模式对照使用更大输出预算。未经语义资格，不启动全量请求。
